# 03. `tcpdump` — 패킷이 실제로 오가는가

`ping`과 `nc`는 "됐다/안 됐다"만 알려준다. `tcpdump`는 **실제로 무슨 패킷이 오가는지**를 보여준다.
"나가긴 하는데 안 들어온다"와 "아예 안 나간다"를 구분할 수 있는 유일한 도구다. 이 구분이 원인을 반으로 좁힌다.

sudo가 필요하다.

## 옵션

| 옵션 | 뜻 |
|---|---|
| `-n` | 이름 해석 안 함 (IP·포트를 숫자로) |
| `-i` | 인터페이스 지정 (`any`도 가능) |
| `-e` | 이더넷 헤더까지 표시 |
| `-A` | 페이로드를 ASCII로 |
| `-c` | 몇 개만 잡고 종료 |
| `-w` | 파일로 저장 (나중에 Wireshark로 열기) |

> **`-n`은 거의 항상 붙인다.** 없으면 DNS 역조회 때문에 출력이 느려지고,
> **DNS 자체가 문제일 때는 아예 멈춰버린다.** 진단 중에 도구가 멈추면 최악이다.

## 필터 문법

```bash
sudo tcpdump -ni ens3 udp port 51820          # 특정 포트
sudo tcpdump -ni any icmp                     # 모든 인터페이스의 ICMP
sudo tcpdump -ni ens3 host 203.0.113.11       # 특정 상대와의 통신만
sudo tcpdump -ni ens3 tcp port 6443           # apiserver 트래픽
sudo tcpdump -ni wg0                          # 터널 내부만
sudo tcpdump -ni ens3 'udp port 51820 and host 203.0.113.11'
```

`and` / `or` / `not`으로 조합한다. 공백이 들어가면 따옴표로 감싼다.

## 출력 읽는 법

```
16:04:12.345678 IP 203.0.113.11.54321 > 10.0.0.169.51820: UDP, length 6
                   └─ 출발지 IP.포트 ─┘   └─ 목적지 IP.포트 ─┘
```

TCP는 플래그가 함께 나온다:

```
IP 10.10.0.1.43210 > 10.10.0.2.6443: Flags [S], seq 123456789
IP 10.10.0.2.6443 > 10.10.0.1.43210: Flags [S.], seq 987654321, ack 123456790
IP 10.10.0.1.43210 > 10.10.0.2.6443: Flags [.], ack 1
```

| 플래그 | 뜻 |
|---|---|
| `[S]` | SYN — 연결 요청 |
| `[S.]` | SYN-ACK — 수락 응답 |
| `[.]` | ACK |
| `[P.]` | PSH-ACK — 데이터 전송 |
| `[F.]` | FIN — 정상 종료 |
| `[R]` | RST — **거부** (REJECT 방화벽 또는 리스너 없음) |

> **`[S]`만 반복되고 `[S.]`가 안 오면** → 요청은 나가는데 응답이 없다. 상대 방화벽이 DROP 중이거나 리스너가 없다.
> **`[R]`이 즉시 오면** → 상대가 명시적으로 거부했다. REJECT 규칙이거나 그 포트에 아무도 없다.

## 진단에서 쓰는 방식

핵심은 **양쪽에서 동시에 잡는 것**이다. 어느 쪽에서 사라지는지가 답이다.

| 보내는 쪽 | 받는 쪽 | 결론 |
|---|---|---|
| 안 보임 | — | 로컬 문제 (라우팅, 로컬 방화벽) |
| 보임 | 안 보임 | **중간에서 차단** — 클라우드 보안 목록 |
| 보임 | 보임 | 네트워크는 정상. 애플리케이션 문제 |

```bash
# 받는 쪽에서 먼저 대기
sudo tcpdump -ni ens3 udp port 51820

# 보내는 쪽에서 쏘기
echo hello | nc -u -w2 198.51.100.22 51820
```

## OCI에서 주의 — 목적지가 사설 IP로 보인다

```
IP 203.0.113.11.54321 > 10.0.0.169.51820: UDP, length 6
                        └─ 공인 IP가 아님 ─┘
```

OCI가 공인 IP를 인스턴스 앞단에서 **1:1 NAT**로 사설 IP에 매핑하기 때문이다.
노드 자신은 공인 IP를 인터페이스에 갖고 있지 않다:

```bash
ip addr show ens3    # → 10.0.0.155/24 뿐
```

이것이 `kubeadm init`의 `--apiserver-advertise-address`에 공인 IP를 주면 안 되는 이유다.
kubelet과 apiserver는 **자기 인터페이스에 실제로 있는 주소**만 바인딩할 수 있다.
