# 01. `ping` — 호스트에 IP가 닿는가 (L3)

ICMP Echo Request를 보내고 Echo Reply가 오는지 본다. **IP 계층(L3)** 확인용이다.
"저 호스트가 살아 있고 경로가 있는가"까지만 알려준다. 특정 포트가 열렸는지는 알 수 없다 → 그건 [`02_nc.md`](02_nc.md).

## 옵션

`-c`가 없으면 Linux에서는 **Ctrl+C를 누를 때까지 무한히** 보낸다. (Windows만 기본 4개)

| 옵션 | 뜻 | 예시 |
|---|---|---|
| `-c` | count — 보낼 패킷 **개수** | `-c3` = 3개 |
| `-W` | 응답 **대기 시간**(초) | `-W1` = 1초 기다리고 포기 |
| `-i` | 보내는 **간격**(초) | `-i0.2` = 0.2초마다 |
| `-s` | 패킷 **크기**(바이트) | `-s1400` = MTU 문제 확인 |
| `-n` | 이름 해석 안 함 | DNS가 느릴 때 |

`-c3`과 `-c 3`은 동일하다. 붙여 써도 되고 띄어 써도 된다.

> `-c`(개수)와 `-W`(대기)를 특히 헷갈리기 쉽다.
> `ping -c2 -W3` = "2개 보내되, 각 응답을 최대 3초까지만 기다린다"

## 실전 조합

```bash
ping -c3 -W1 10.0.0.169         # 빠른 확인 — 안 되면 즉시 포기
ping -c20 10.10.0.2 | tail -2   # 품질 측정 — 손실률과 RTT 요약만
ping -c5 -s1400 10.10.0.2       # MTU 문제 확인 (터널에서 중요)
```

`tail -2`는 마지막 요약 두 줄(손실률, RTT min/avg/max/mdev)만 보겠다는 뜻.
20개 각각의 줄은 볼 필요가 없다.

`-W`를 안 주면 기본 대기가 길어서, 막힌 상대를 확인할 때 한참 멈춘다.

## 출력 읽는 법

```
64 bytes from 10.10.0.2: icmp_seq=1 ttl=64 time=12.3 ms
--- 10.10.0.2 ping statistics ---
20 packets transmitted, 20 received, 0% packet loss, time 19030ms
rtt min/avg/max/mdev = 11.8/12.4/15.1/0.7 ms
```

| 항목 | 의미 |
|---|---|
| `icmp_seq` | 순번. 건너뛴 번호가 있으면 그 패킷이 유실된 것 |
| `ttl` | 남은 홉 수. 값이 크게 다르면 경로가 바뀐 것 |
| `time` | RTT(왕복 지연) |
| `packet loss` | 0%가 아니면 경로 품질 문제 |
| `mdev` | 지연의 **흔들림**. 이 값이 크면 평균이 낮아도 불안정하다 |

> etcd는 피어 지연에 민감하다. Phase 4에서 HA를 구성할 계획이라면 `mdev`를 지금 측정해 기록해 둘 것.

## ⚠️ ping 실패 = 연결 안 됨, 이 아니다

ICMP는 방화벽에서 가장 먼저 막히는 프로토콜이다. **OCI 기본 보안 목록은 ICMP를 일부 타입만 허용한다.**

| 상황 | ping | TCP |
|---|---|---|
| ICMP만 차단 | ❌ | ✅ |
| 해당 포트만 차단 | ✅ | ❌ |
| 경로 자체가 없음 | ❌ | ❌ |

즉 **ping 결과만으로는 아무것도 확정할 수 없다.** 반드시 `nc`로 포트를 함께 확인한다.
이 저장소의 Phase 0에서 사설 IP ping이 실패하는 것은 방화벽이 아니라 **경로 자체가 없기 때문**이다 (다른 VCN).
