# 04. `ss` — 데몬이 포트를 잡고 있는가

여기까지 왔는데 안 된다면, 상대가 아니라 **내 쪽에 아무도 안 듣고 있을** 가능성을 본다.
`ss`는 소켓 상태를 보여준다. `netstat`은 deprecated이므로 `ss`를 쓴다.

## 옵션 조합

옵션은 조합해서 외우는 게 빠르다.

| 글자 | 뜻 |
|---|---|
| `-l` | listening — 대기 중인 소켓만 |
| `-n` | 숫자로 (포트를 이름으로 안 바꿈) |
| `-t` | TCP |
| `-u` | **UDP** |
| `-p` | 프로세스 정보 (sudo 필요) |
| `-a` | 전부 |

```bash
ss -lntp          # TCP 리스닝 포트 + 프로세스   ← 가장 많이 씀
ss -lunp          # UDP 리스닝 포트 + 프로세스   ← WireGuard 확인용
ss -tnp           # 연결된 TCP 세션
ss -s             # 요약 통계
```

> **`-u`를 빼먹는 실수가 잦다.** 기본 출력에 UDP는 안 나온다.
> WireGuard(51820)는 UDP라 `ss -lntp`로는 절대 안 보인다.

## 출력 읽는 법

```
State   Recv-Q  Send-Q  Local Address:Port   Peer Address:Port  Process
LISTEN  0       4096          0.0.0.0:22          0.0.0.0:*      users:(("sshd",pid=1234,fd=3))
UNCONN  0       0             0.0.0.0:51820       0.0.0.0:*      users:(("wg",pid=0,fd=0))
```

| 항목 | 의미 |
|---|---|
| `LISTEN` | TCP 대기 중 |
| `UNCONN` | UDP (연결 개념이 없으므로 정상 상태) |
| `0.0.0.0:22` | **모든 인터페이스**에서 대기 |
| `127.0.0.1:6443` | **루프백만** — 외부에서 접근 불가 ⚠️ |
| `Recv-Q` | 쌓인 수신 큐. 계속 늘면 애플리케이션이 처리를 못 하는 중 |

> **바인딩 주소를 반드시 볼 것.** `127.0.0.1`에만 묶여 있으면 방화벽을 아무리 열어도 외부에서 못 붙는다.
> "포트는 열었는데 왜 안 되지"의 흔한 원인이다.

## 클러스터에서 확인할 포트

```bash
ss -lntp | grep -E '6443|2379|2380|10250|10256'
```

| 포트 | 데몬 |
|---|---|
| 6443 | kube-apiserver |
| 2379–2380 | etcd (클라이언트 / 피어) |
| 10250 | kubelet |
| 10256 | kube-proxy 헬스체크 |

`kubeadm init` 후 이 포트들이 안 보이면 해당 컴포넌트가 뜨지 않은 것이다.
→ `sudo crictl ps -a`, `journalctl -u kubelet -f`로 이어서 확인.
